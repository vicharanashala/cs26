2. EXECUTIVE SUMMARY
================================================================================

Vicharanashala OAQ (Once Asked Questions) is a gamified, peer-to-peer query
resolution platform designed to streamline intern onboarding and eliminate
redundant mentor queries. Built on the MERN stack with real-time Socket.io
synchronization, the platform incentivizes interns to resolve each other's
technical roadblocks through Skill Points (SP), leaderboards, auto-promotion
mechanisms, and content quality gates. Every question is asked and answered
exactly once, then persisted as a searchable baseline knowledge artifact for
all future cohorts.

Key achievements:
  - 15 fully implemented features covering query resolution, AI chat,
    duplicate prevention, real-time sync, nested discussions, and gamification
  - Automated content quality auditing (Yaksha-mini) with real-time preview
  - Dual-algorithm duplicate query prevention (word-level + character overlap)
  - AI-powered RAG chat widget with GPT-3.5-turbo streaming (optional key)
  - Real-time Socket.io synchronization across all connected sessions
  - Fully responsive design with WCAG AA-compliant dark/light mode


3. INTRODUCTION
================================================================================

Interns joining new organizations frequently encounter blocking technical and
administrative issues. Without a structured knowledge-sharing system, the same
questions are asked repeatedly, leading to mentor burnout and slow onboarding.

Vicharanashala OAQ & Threads solves this by creating a self-sustaining
knowledge ecosystem where:
  - Interns are incentivized to help peers through SP rewards and leaderboards
  - Every resolved answer becomes a permanent, searchable knowledge asset
  - Duplicate questions are detected before they are raised
  - Content quality is enforced by automated audits and community voting
  - Real-time synchronization keeps all participants in sync

The platform serves as the core knowledge-sharing and query-tracking portal
within the larger Vicharanashala internship onboarding ecosystem.

4.2 USE-CASE DIAGRAM (Textual)

  Actor: Intern
    - Register / Login (JWT or Google OAuth)
    - Raise a new query (checked for duplicates)
    - Browse OAQ Library (13 baseline FAQ categories)
    - View and resolve open FCFS queries (first-come, first-served)
    - Submit community replies on resolved queries
    - Upvote / downvote issues and replies
    - View trending feed (top 15 resolved)
    - Voice search FAQs and listen to answers via speech playback
    - Access Yaksha Mini AI chat widget
    - Create and participate in nested thread discussions
    - View personal SP dashboard (overview, ledger, leaderboard)
    - View user profiles

  Actor: Mentor (extends Intern)
    - Flag low-quality replies
    - Lock / unlock thread discussions
    - Promote best replies
    - Sign off resolutions

  Actor: Admin (extends Mentor)
    - Manage user roster and SP balances
    - CRUD over dynamic sections
    - Override FCFS queries
    - Award custom SP on thread close

  Actor: Superadmin (extends Admin)
    - Register / provision new Admins
    - Trigger database seeder tools

4.3 DATA FLOW DIAGRAM (FCFS Resolution Flow)

  Intern A posts query
       |
       v
  POST /api/oaq -> Duplicate check -> Save to MongoDB
       |
       v
  Socket.io broadcast: issue:created -> All connected clients
       |
       v
  Intern B sees open query on Resolver Board
       |
       v
  Clicks "Resolve" -> Server sets lockedBy + lockExpiry (30s TTL)
       |
       v
  Intern B submits answer -> Yaksha-mini audit
       |
       +--(fail)--> Reject with -20 SP penalty
       |
       +--(pass)--> Answer enters communityReplies (pending)
                     Socket.io broadcast: issue:resolved-attempt
       |
       v
  Community upvotes/downvotes -> checkAutoPromote()
       |
       +--(upvotes >= 3)--> Status=Resolved, +50 SP to resolver
                            Socket.io broadcast: issue:resolved
       |
       +--(<3 upvotes)--> Remains pending

4.4 STALE QUERY AUTO-ESCALATION FLOW

  staleWatcher (runs every 10 min via node-cron)
       |
       v
  Queries open issues with createdAt > 24h & no communityReplies
       |
       v
  Highlights as stale (red/amber on Resolver Board)
       |
       v
  If priority escalation eligible -> set priority=HIGH
                                    Socket.io alert to mentors

6. FEATURE SPOTLIGHT

--------------------------------------------------------------------------------
SPOTLIGHT 1: Duplicate Query Prevention
--------------------------------------------------------------------------------
Purpose: Prevent redundant queries before they are raised, reducing clutter
and guiding interns to existing answers.
Impact: Eliminates duplicate questions at the source, keeping the resolver
board clean and directing interns to already-resolved solutions.
Technical highlight: Dual-algorithm scoring (word-level Jaccard 50% + character
bigram overlap 50%) with color-coded warnings (red >=70%, amber >=50%,
green <50%).

[https://drive.google.com/file/d/1S1Nc-TTmoqpOTtvrY79F-ggARAPPNz3c/view?usp=sharing]

--------------------------------------------------------------------------------
SPOTLIGHT 2: FCFS Resolver Board with Collision Detection
--------------------------------------------------------------------------------
Purpose: Gamify query resolution by letting interns compete to claim and
resolve open issues first.
Impact: Drives fast, competitive resolution. 30-second TTL lock prevents
double-work; collision alerts on concurrent attempts.
Technical highlight: MongoDB lock with TTL index; Socket.io broadcasts for
real-time lock state.

[https://drive.google.com/file/d/1Lh2WJMFEhspxA37XtJWn7_TDhSnD4Qz6/view?usp=sharing]

--------------------------------------------------------------------------------
SPOTLIGHT 3: Real-Time Sync Broadcaster
--------------------------------------------------------------------------------
Purpose: Instant synchronization across all online sessions without manual
refreshes.
Impact: Every action (issue created, resolved, upvoted, escalated) is visible
to all connected users immediately.
Technical highlight: Socket.io event-driven architecture with reconnection
banner when connection drops.

7. CHALLENGES & LIMITATIONS
================================================================================

CHALLENGES

  1. Real-Time Collision Handling
     Managing concurrent FCFS resolution attempts required implementing a
     30-second TTL lock with MongoDB expiry index. Handling edge cases like
     network drops during the lock window was non-trivial.

  2. Duplicate Detection Accuracy
     Balancing false positives vs false negatives in the dual-algorithm scorer
     required extensive tuning of the 35% threshold and the 50/50 weight split
     between word-level and character-level matching.

  3. Yaksha-mini Content Gate
     Defining "meaningful content" heuristically (word ratio >40%, keyboard
     pattern detection) was challenging — overly strict gates frustrated users,
     while lax gates allowed spam through.

  4. Socket.io Scaling
     Broadcasting to all connected clients on every event scales well for
     cohort sizes but would need namespace/room partitioning for larger
     organizations.

  5. RAG Context Retrieval
     Using $regex for knowledge base search is effective for exact/partial
     matches but lacks semantic understanding. Upgrading to vector search
     (MongoDB Atlas Search) would improve relevance.

LIMITATIONS

  - No mobile native app (responsive web only)
  - OpenAI API key required for GPT-3.5-turbo streaming (falls back gracefully)
  - Stale watcher uses polling (node-cron every 10min) rather than event-driven
  - No WebSocket fallback for environments that block WebSocket connections
  - No rate limiting on API endpoints (potential abuse vector)
  - No automated test suite (manual testing only)
  - No CI/CD pipeline (manual git push deployment)
  - Google OAuth requires client ID configuration per deployment

9. CONCLUSION

Vicharanashala OAQ & Threads successfully delivers a self-sustaining,
gamified knowledge-sharing platform that transforms intern onboarding from a
mentor-dependent bottleneck into a collaborative, peer-driven ecosystem. All
15 planned features have been fully implemented, including:

  - A real-time FCFS resolver board with collision-safe locking
  - Yaksha-mini automated content quality auditing
  - Community-driven auto-promotion and auto-escalation

  - An AI-powered RAG chat widget with streaming GPT-3.5-turbo

  - Nested thread discussions with mentor moderation

The MERN stack proved well-suited for this project, with MongoDB's flexible
document model enabling nested community replies and Socket.io providing
seamless real-time synchronization. The platform is production-ready, deployed
on GitHub, and accessible to all cohort members.
